# JD Amulet Switcher

Макро-переключатель амулетов для Jade Dynasty (клиент 3.1.1, оконный режим).
Нажимаете клавишу скилла — программа сама жмёт клавишу амулета, выдерживает паузу N мс и жмёт скилл.
Работает только через эмуляцию клавиатуры: без чтения памяти, инъекций, захвата экрана и кликов мышью.

## Сборка

Нужен .NET 8 SDK.

```bat
:: лёгкий exe (~0.4 МБ), на ПК нужен .NET 8 Desktop Runtime
dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained false

:: exe без зависимостей (~70 МБ)
dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true --self-contained true
```

Результат: `bin\Release\net8.0-windows\win-x64\publish\JdAmuletSwitcher.exe`.
Конфиг `JdAmuletSwitcher.json` создаётся рядом с exe.

## Структура

| Слой | Файл | Назначение |
|---|---|---|
| Native | `Native/NativeMethods.cs` | P/Invoke, структуры INPUT/KBDLLHOOKSTRUCT |
| KeyboardHook | `Input/KeyboardHook.cs` | WH_KEYBOARD_LL на своём потоке с циклом сообщений |
| InputSender | `Input/InputSender.cs` | выделенный поток ввода, SendInput (скан-коды) / PostMessage |
| PrecisionDelay | `Input/PrecisionDelay.cs` | высокоточный waitable-таймер + spin на последние 1–2 мс |
| GameWindowTracker | `Game/GameWindowTracker.cs` | поиск окна игры и слежение за ним через WinEvents |
| MacroEngine | `Engine/MacroEngine.cs` | логика хука, связки, состояние надетого амулета, лог |
| Config | `Config/AppConfig.cs` | профили, JSON |
| UI | `UI/MainForm.cs`, `UI/OverlayBar.cs`, … | окно настроек, трей, оверлей-бар |

## Как это работает

Настраивается список амулетов, у каждого — набор скиллов, которым он нужен:

| Амулет | Скиллы | Пауза |
|---|---|---|
| F1 | 1, 2 | 20 мс |
| F2 | 3, 4, 5 | 20 мс |

Нажали **1** в игре → программа нажимает **F1** (если этот амулет ещё не надет) → пауза → нажимает **1**.
Скилл держится нажатым, пока вы держите клавишу, — как при обычной игре.
Если амулет уже надет, скилл нажимается сразу, без амулета и без паузы.

## Быстрый старт

1. Запустите exe (попросит права администратора — как и клиент игры).
2. «Добавить амулет» (или «Изменить» у примера): щёлкните поле «Клавиша амулета» и нажмите F1;
   щёлкните «Скиллы под амулет» и нажмите по очереди 1, 2. Повторное нажатие клавиши убирает её, Backspace — последнюю.
3. Переключитесь в игру. Над клиентской областью появится панель:
   `[ВКЛ] [⠿] [F1 → 1,2 [Ctrl+1]] …`
   * **ВКЛ / ВЫКЛ** — индикатор макросов, клик по нему тоже включает/выключает;
   * **⠿** — ручка: тяните, чтобы переместить панель в любое место окна игры («Закрепить положение» убирает ручку);
   * кнопка амулета — надеть амулет; зелёная полоска снизу показывает надетый сейчас амулет.

## Если скилл не срабатывает

1. Увеличьте **«Длительность нажатия»** (по умолчанию 30 мс) до 40–60 мс: игра проверяет клавиши раз в кадр
   и пропускает слишком короткие нажатия.
2. Поменяйте «Режим ввода» на **PostMessage в окно игры**.
3. Программа должна быть запущена от администратора. Ошибка с кодом 5 в логе — блокировка UIPI.
4. Проверьте имя процесса (по умолчанию `ElementClient.exe`) и строку «Игра: …» в статусе внизу окна.
5. Если программа считает амулет уже надетым, а это не так, нажмите «Сбросить состояние амулета»
   или включите «Всегда надевать амулет».

## Подбор паузы

1. Поставьте паузу 0 мс (ползунок под таблицей применяется сразу).
2. Если бонус амулета срабатывает не всегда, прибавляйте по 10 мс, пока он не начнёт срабатывать стабильно.
3. В логе для каждого нажатия видны фактическая пауза и время от нажатия клавиши до нажатия скилла.

## Клавиши

* **Pause** — включить или выключить макросы (работает глобально, клавишу можно сменить в настройках).
* Комбинации «надеть» (например, Ctrl+1) надевают амулет без скилла — то же, что кнопка на панели.
* При зажатых Ctrl/Alt/Shift клавиши скиллов уходят в игру без изменений.
